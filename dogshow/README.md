# The Dogshow

The self-contained showcase of the datazimmer ecosystem, and its cross-package end-to-end suite. A fictional kennel federation runs a website of breed registries, kennels, show schedules and result feeds; the dogshow **collects** it with aswan, **parses** it into a typed star schema, **validates** foreign-key integrity, **materializes** a SQL database + ER diagram, and **publishes** a versioned dataset that downstream projects consume by URL.

No external data is read: the federation site is a Flask app served locally, so the whole `collect → run → validate → publish → load` loop runs from a clean checkout.

## What it exercises

| Package | Role in the dogshow | Exercised by |
| --- | --- | --- |
| [aswan](https://github.com/endremborza/aswan) | scrape the site (HTTP + relay handlers, proxy, retries, link cascades), versioned depot, push/pull | `src/collection.py`, `tests/test_collection.py` |
| [atqo](https://github.com/endremborza/atqo) | parallel scheduler + actor slots running collection in subprocess workers | transitively, via aswan `Project.run` |
| [dirark](https://github.com/endremborza/dirark) | content-addressed object store backing the depot | transitively, via the aswan depot |
| [shackleton](https://github.com/endremborza/shackleton) | `TableRepo` storage: validated writes, partitioning, `max_records` splitting, append, compaction | `tests/test_table.py` |
| [sqlmermaid](https://github.com/endremborza/sqlmermaid) | ER diagram from the SQL metadata | `tests/test_sql.py`, `tests/test_docs.py` |
| **datazimmer** | `Entity` + FK metadata, `Table`, `Pipeline`, `validate`, `to_sql`, `publish`/`pull`/`load`/`load_dependency`/`schema codegen`, config, CLI, `DzAswan` | every test module; cross-project reuse in `tests/test_reuse.py` |

## The schema

[`src/meta.py`](src/meta.py) holds the `Entity` classes, shaped to cover the metadata surface: a nullable scalar (`Breed.origin`), a nullable foreign key (`Dog.kennel`), a partitioned table (`Result` by show), and two FK-only aggregates with no index of their own (`BreedWins`, `KennelStanding`).

The ER diagram at [`docs/schema.md`](docs/schema.md) is generated by `dz draw`; `tests/test_docs.py` fails when it drifts from the schema, and `make erd` regenerates it.

## Layout

- `src/` — the project: `meta.py` (entities), `tables.py` (the pipeline + tables), `collection.py` (aswan handlers + the `DzAswan` collector), `parsing.py` and `analytics.py` (the steps).
- `tests/` — one module per feature area; `conftest.py` boots the site and collects once per session, then clones the built outputs into a temp project per test. `tests/site/` is the Flask federation + relay worker.
- `showcase.py` — the real `dz` CLI loop against the live site, bounded (`make showcase`).
- `report.py` — the suite under coverage → `REPORT.md` + `coverage/html/`.
- `docker/` — a self-contained runner that adds a real rsync-over-ssh target.
- `sitecustomize.py` — starts coverage in aswan's spawned workers.

## Running

```bash
cd dogshow
make test        # the suite; s3 via moto, http via a throwaway server, ssh skips unless DOGSHOW_SSH_REMOTE is set
make report      # the suite under coverage -> REPORT.md + coverage/html
make showcase    # site + relay up, `dz run → validate → draw → sql → publish → pull`, site down
make serve       # the site long-lived, for hand-driven `dz` sessions
make erd         # regenerate docs/schema.md
docker compose -f docker/compose.yaml up --build --abort-on-container-exit   # adds the ssh backend
```

Every target runs through `uv` against the editable sibling checkouts pinned in `pyproject.toml`; artifacts stay inside `dogshow/` and `make clean` removes them.

## Coverage

[`REPORT.md`](REPORT.md) is the single source for runtime, per-library coverage of all six packages and the slowest tests; `coverage/html/index.html` is the browsable report, filtered to library source. No number is copied into prose.

Collection runs handler code in spawned subprocesses and the relay in a thread, so `[tool.coverage]` measures both (`concurrency = ["multiprocessing", "thread"]`, `parallel`, `sigterm`) and `sitecustomize.py` starts coverage in each worker. Worker code is under-reported, since atqo terminates workers before coverage fully flushes; the remaining gap is what the dogshow leaves to each library's own suite (`zenodo`, aswan's monitor app, legacy depot converter, browser handler and authenticated proxy).

The Docker runner ssh's to itself for the `ssh` backend and runs as the host user, so it leaves no root-owned files. Nothing can hang it: `--timeout` bounds each test, `--session-timeout` the session, and `report.py` runs pytest in its own process group under `DOGSHOW_SUITE_TIMEOUT`, killing the group on expiry.
